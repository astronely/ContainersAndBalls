# Тестовое задание

## Ограничения
- 1 <= n <= 100
- 0 <= количество шаров в одном контейнере <= 10^9

## Идея решения
Чтобы понять, возможно ли отсортировать контейнеры, используя только операцию
замены двух шаров между собой, нужно посчитать сумму всех шаров по строкам и столбцам. 
Если количество строк с итоговой суммой X совпадает с количеством столбцов с итоговой суммой X,
то сортировка возможна, если нет, то невозможна.

## Почему это работает
Пример пошаговой сортировки входной матрицы:
```
             sumX          
    [1, 4, 0] 5         [3, 2, 0 ] 5         [5, 0, 0 ] 5         [5, 0, 0 ] 5
    [2, 2, 2] 6     ->  [0, 4, 2 ] 6     ->  [0, 4, 2 ] 6     ->  [0, 6, 0 ] 6
    [2, 0, 8] 10        [2, 0, 8 ] 10        [0, 2, 8 ] 10        [0, 0, 10] 10
sumY 5  6  10            5  6  10             5  6  10             5  6  10
```
- sumX[i]: Сумма в i-ом столбце - количество шаров i-го цвета
- sumY[j]: Сумма в j-ой строке - количество шаров в j-той строке

Для того чтобы переместить все шары 1-го столбца в, допустим, 1-ую строку,
нужно совершить sumY[0] - matrix[0][0] = 5 - 1 = 4 операций. Итого, включая имеющийся шар 1-го цвета - потребуется 5 шаров в сумме.
Если бы matrix[i][j] = 0, то пришлось бы совершить 5 операций для переноса всех шаров 1-го
цвета в 1-ую строку, на что потребовалось бы 5 шаров других цветов,
то есть сумма по 1-ой строке должна быть sumY[0] = 5 в любом случае, иначе будет невозможно переместить все шары 1-го цвета в 1-ую строку.
По аналогии, это будет верно для каждой строки и столбца. \
То есть, необходимо найти такие sumX[i] и sumY[j], что они будут равны. 
Тогда будет возможен перенос всех шаров j-го цвета в i-ую строку. Если каждой sumX[i] найдется пара sumY[j], то ответ **yes**, иначе **no**. \
Также можно заметить, что на каждом шаге sumX и sumY остаются неизменными на каждом шаге. \
При этом, необязательно чтобы sumX[i] = sumY[i] как в примере, это могут быть любые строки и столбцы.
Для этого в решении применяется либо сортировка, либо мапа.

## Решение 1 (solveWithSort)
### Временная сложность
- **O(n^2)** считывание
- **O(n*logN)** сортировка
- **O(n)** получение ответа
- **O(n^2 + n*logN) = O(n^2)** Итоговая сложность

### Память
- **O(n)** массивы сумм шаров по строкам/столбцам

## Решение 2 (solveWithMap)
### Временная сложность
- **O(n^2)** считывание
- **O(n)** заполнение мапы
- **O(n)** получение ответа
- **O(n^2 + n + n) = O(n^2)** Итоговая сложность

### Память
- **O(n)** массивы сумм шаров по строкам/столбцам
- **O(2n) = O(n)** мапа для получения ответа (2n в худшем случае, если суммы шаров по строкам и столбцам полностью не совпадают)

## Сравнение решений
- Временная сложность, как минимум, будет **O(n^2)** из-за формата входных данных (считывание матрицы NxN)
- Оба решения имеют одинаковую временную сложность - **O(n^2)**, 
что отлично в рамках задачи, поскольку **1 <= n <= 100**, значит максимум **O(10000)** - очень быстро
- Оба решения имеют одинаковые затраты по памяти **O(n)**
- Первое решение использует **сортировку** полученных массивов сумм шаров
- Второе решение создает новую **map[int]int**: 
добавляет +1 по ключу (сумма шаров у i-ой строки), 
отнимает -1 по ключу (сумма шаров у i-го столбца)
- Первое решение не использует дополнительную **map[int]int**, но оценка памяти такая же **O(n)** 
- Второе решение не использует **сортировку** за **O(n*logN)**, но итоговая оценка сложности такая же **O(n^2)**
